PODCAST 68 — GARBAGE COLLECTION IN JAVASCRIPT
Approximate runtime: 5 minutes

JavaScript automatically manages memory through garbage collection. Engineers still need to understand object reachability. An object can be collected when nothing reachable from the program can access it. Local variables often become collectible after their scope is gone, but references retained by globals, caches, listeners, timers, or closures can keep objects alive. Garbage collection itself consumes CPU. Creating enormous numbers of temporary objects can create pressure even when there is no leak. Avoid assuming that forcing collection is a normal application strategy. Instead, control object lifetimes and avoid unnecessary retention. Large caches should have explicit policies. Event listeners should follow component lifecycles. Long-lived processes should periodically be examined for retained objects. Memory profiling can show which objects remain reachable and why. The goal is not to manually manage memory like a language without garbage collection. The goal is to understand ownership and lifetime so the runtime can manage memory effectively.
