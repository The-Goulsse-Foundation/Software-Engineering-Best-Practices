PODCAST 74 — BUNDLING AND CODE SPLITTING
Approximate runtime: 5 minutes

Bundling combines modules into files that can be delivered efficiently to a browser or runtime. Code splitting allows parts of an application to be loaded only when needed. The goal is not simply the smallest number of files. Network behavior, caching, startup work, and user journeys all matter. A large initial bundle can delay startup. Too many tiny chunks can create excessive requests or coordination overhead. Analyze actual bundle composition. Remove unused dependencies and avoid importing enormous libraries for tiny features when alternatives exist. Long-lived shared chunks can improve caching when their contents change infrequently. Dynamic imports can defer rarely used features. Be careful with circular dependencies and side effects because they can affect tree-shaking. Measure the production build rather than assuming development behavior represents production. Bundling is a delivery optimization. The correct strategy depends on how users actually navigate and load the application.
