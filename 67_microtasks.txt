PODCAST 67 — MICROTASKS, PROMISES, AND EXECUTION ORDER
Approximate runtime: 5 minutes

Promises introduce microtasks, which can affect execution order in JavaScript. A promise callback does not normally execute immediately when the promise is resolved. It is scheduled to run after the current synchronous work completes and according to the runtime's job scheduling rules. This matters when code mixes synchronous operations, promises, and timers. Engineers should avoid relying on obscure ordering behavior when a clearer design is possible. Long chains of microtasks can also delay other work. The practical approach is to keep asynchronous control flow readable and avoid clever scheduling tricks. Use async and await when they make dependencies obvious. When debugging ordering problems, reduce the example to a small reproduction and identify which work is synchronous and which is queued. Tests should not depend on accidental timing. If correct behavior requires waiting for a particular event, represent that dependency explicitly. Understanding microtasks is valuable because it explains why a promise callback may run before a timer even when both were scheduled after the same synchronous operation.
