PODCAST 70 — CANCELLATION WITH ABORTCONTROLLER
Approximate runtime: 5 minutes

Cancellation is an important part of modern asynchronous JavaScript. A request that is no longer needed should not necessarily continue consuming resources. AbortController provides a standard cancellation signal used by many web APIs and supported in modern server-side JavaScript environments. Pass a signal through layers rather than hiding cancellation inside one function. A service calling another service can connect the caller's deadline to the downstream request. Cancellation should be treated as a normal outcome rather than an unexpected exception in every context. Clean up resources when cancellation occurs. UI applications benefit when requests for obsolete screens or searches can be canceled. Backend services can stop work when a client disconnects or a deadline expires, depending on the architecture. Cancellation is especially valuable for expensive operations. It reduces wasted computation and network activity. But cancellation semantics should be documented. A canceled operation may leave partial work, so idempotency and cleanup remain important. Reliable asynchronous systems define not only how work starts, but also how work stops.
