PODCAST 79 — ELIMINATING FLAKY JAVASCRIPT TESTS
Approximate runtime: 5 minutes

A flaky test passes and fails without a meaningful code change. Flakiness destroys confidence in automation. Common causes include timing assumptions, shared state, random data, network dependencies, order dependence, and incomplete cleanup. Avoid arbitrary sleeps when possible. Wait for a real condition or event. Isolate test data. Reset mocks and state between tests. Control clocks and randomness when they affect behavior. External services should be replaced or controlled in tests unless the test specifically validates integration with them. Parallel test execution can expose hidden shared state. When a flaky test appears, investigate rather than repeatedly rerunning until it passes. Record enough context to reproduce the failure. Quarantining a flaky test can be useful temporarily, but permanent quarantine turns missing coverage into invisible risk. Reliable tests are infrastructure. They should provide fast, repeatable information about the health of the codebase.
