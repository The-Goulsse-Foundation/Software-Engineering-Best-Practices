PODCAST 69 — CONCURRENCY CONTROL IN JAVASCRIPT
Approximate runtime: 5 minutes

JavaScript can perform many asynchronous operations concurrently even though ordinary JavaScript execution is often single-threaded per execution context. Concurrency creates opportunities and hazards. Launching ten independent requests together may reduce total waiting time. Launching ten thousand may overwhelm a dependency. Use bounded concurrency when workloads are large. A worker pool or queue can limit simultaneous operations. Be careful when several asynchronous functions update shared state. Although JavaScript avoids many traditional data races within one thread, asynchronous interleaving can still produce logical races. Two operations may read old state and then write conflicting results. Database transactions, atomic operations, version checks, or serialized updates may be required. Cancellation is another part of concurrency. If a user navigates away, continuing expensive work may waste resources. Concurrency should be designed rather than accidentally produced by loops that create thousands of promises. The question is not only whether work can run concurrently, but how much concurrency the system can safely sustain.
