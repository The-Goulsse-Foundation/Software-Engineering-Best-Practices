PODCAST 71 — SCHEMA-VALIDATED CONFIGURATION
Approximate runtime: 5 minutes

Configuration is external input, even when it comes from environment variables controlled by your deployment system. Validate it at startup. Required URLs should be valid URLs. Ports should be valid numbers. Boolean settings should not rely on surprising string conversions. Enumerated settings should accept only documented values. Secrets should be present when required but should never be printed. Centralize configuration loading so application code does not repeatedly interpret environment variables. A configuration object can provide stable internal types. Fail fast when required configuration is invalid. This is usually better than starting successfully and failing later during the first production request. Separate configuration from credentials where the operational environment benefits from that distinction. Document which settings are required, optional, or environment-specific. Configuration validation is inexpensive and prevents an entire class of deployment errors. Treat startup configuration as a contract between infrastructure and application code.
